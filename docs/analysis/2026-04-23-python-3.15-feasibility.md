## 3. 3.13 → 3.15 の主な破壊的/非互換変更

出典: [docs.python.org/3.15/whatsnew/3.15.html](https://docs.python.org/3.15/whatsnew/3.15.html)（alpha 8 版ドキュメント）

### 新機能（影響大）
- **PEP 810: Explicit lazy imports** — `lazy import json` 構文、`-X lazy_imports`。起動時間短縮だが、import 副作用に依存する古いコードを壊す可能性。
- **PEP 814: frozendict 組込型** — ハッシュ可能な不変 dict。
- **PEP 798: Comprehension 内 `*`/`**` unpacking** — `[*L for L in lists]`。
- **PEP 799: profiling パッケージ** — `profiling.sampling`（Tachyon, 最大 1 MHz サンプリング, flamegraph 出力）。既存の `cProfile` は `profiling.tracing` に統合。
- **PEP 803: abi3t**（free-threaded 用 Stable ABI）— C 拡張の free-threaded 対応が楽に。
- **PEP 686: UTF-8 default encoding** — `open()` が locale 非依存で UTF-8。`encoding='locale'` で旧動作復元。
- **PEP 747: `TypeForm`** — 型式を明示。
- **JIT 強化**（PEP 744 更新）— LLVM 21 依存、x86-64 で +6–7%、ARM64 macOS で +12–13%（幾何平均）。ただし JIT はデフォルト off。
- **Free-threaded build（PEP 703）**: `3.15.0a8t` タグあり。default build は依然 GIL あり。

### 削除された API（移行時チェック必須）
| モジュール | 削除項目 |
| --- | --- |
| `ctypes` | `SetPointerType()` |
| `glob` | `glob0()`, `glob1()` |
| `http.server` | `CGIHTTPRequestHandler`, `--cgi` flag |
| `pathlib` | `PurePath.is_reserved()` |
| `platform` | `java_ver()` |
| `sre_compile` / `sre_constants` / `sre_parse` | **モジュール全体** |
| `threading` | `RLock` の任意位置引数 |
| `typing` | `ByteString`（`__all__` 除外）、`NamedTuple` の keyword 引数構文、ゼロフィールド `TypedDict` |
| `wave` | `getmark()`, `setmark()`, `getmarkers()` |
| `zipimport` | `zipimporter.load_module()` |
| `collections.abc` | `ByteString`（`__all__` 除外、warning） |

### 新たな deprecation
- `base64`: 代替アルファベット decode 時の `+`/`/` 混在。
- `-b`/`-bb` CLI オプション（3.17 で no-op 化予定）。
- `hashlib`: `string=` キーワード引数。
- `re.match()` → `re.prefixmatch()` への soft deprecation（削除はしない）。

### AIOS コードへの影響スキャン（grep ベース目視）
`~/skills/scripts/*.py` を `glob0|glob1|sre_|is_reserved|CGIHTTP|java_ver|zipimporter.load_module|ByteString|NamedTuple\(.*=` でサーベイ推奨。特に注意: `mlx-embed-server-standalone.py` は `mlx.core`, `mlx.nn`, `tokenizers`, `fastapi`, `uvicorn`, `numpy` のみ使用（L45–50 で確認済）— 削除 API への依存はほぼない見込み。

### 致命的ブロッカー
1. **mlx core に cp315 wheel がない**。MLX は `.metal` シェーダと C++ 拡張のバインディングで、**pure Python ではない**。cp315 wheel がリリースされるまで source ビルドも事実上不可能（Metal toolchain + Apple Silicon 固有の問題）。AIOS の MLX embed / MLX generate の双方がここで止まる。
2. **sentence-transformers は 3.14 すら未宣言**（上記マトリクス）。これは 3.15 以前に 3.14 移行時点でも要確認ポイント。(unverified: ~/skills/ 内での sentence-transformers 使用有無は本調査では未確認)

## 5. 移行戦略（recommended staging）

### フェーズ 0（現在〜2026-10-01）: **HOLD**
- pyenv の既存 3.13.0 / 3.13.2 を維持。
- 3.15 は **一切触らない**（mlx wheel なし、Beta すら未到達）。
- ただし `pyenv update` で plugin は最新化しておくと、将来 3.15.0a8/Beta1 を試す時に即応できる。

### フェーズ 1（2026-10-01 直後, 3.15.0 GA 後）: **観察のみ**
- PyPI で `mlx` / `mlx-lm` / `fastapi` / `uvicorn` / `numpy` / `transformers` の classifier に `Python :: 3.15` が追加されるか観察。
- 経験則として主要 wheel ベンダ（numpy, torch, mlx）が 3.15 wheel を出すまで **2〜8 週間** のラグが通常発生。

### フェーズ 2（全主要 dep が cp315 wheel 対応後）: **side-by-side install**
- `pyenv install 3.15.X`（その時点の最新 stable）。3.13.0 と 3.13.2 は維持。
- **先に移行する候補（安全順）**:
  1. `locomo-eval.py`（評価ハーネス、本番外、依存少）
  2. `aios_mlx_lock.py`（ロックのみ、mlx 依存なし）
  3. `convert-bge-coreml.py`（オフライン変換、CoreML 側依存）
- **後回し候補**:
  4. `mlx-embed-server-standalone.py`（port 3161 本番、MLX 依存）
  5. `mlx-generate-wrapper.sh` → `mlx_lm.server`（port 3162 本番、MLX 依存）
  6. `MLXEmbedServerStandalone.app`（Nuitka bundle、再ビルド要）

### フェーズ 3（本番切替）
- 各サービス個別に wrapper の `export PATH=...` を 3.13 → 3.15 に差し替え、1 週間 staging。
- `MLXEmbedServerStandalone.app` は **3.13 維持でも可**（.app は bundle 内で完結、外部 Python に非依存）。mlx-generate だけ先行移行も可能。

### ロールバック
- plist を 1 行（`.../3.15.X/bin/python3` → `.../3.13.2/bin/python3`）書き戻すだけ。
- 既に `mlx-generate-wrapper.sh` L7 がこのパターン（pyenv `3.13.2` を PATH に明示）で、ロールバック実績あり。

## 7. 推奨判断: **HOLD**

### 条件付きで GO / STAGED に移す日付条件

- **今すぐ（2026-04-23）**: HOLD。理由は単純で、**3.15 は Alpha 8 であり GA まで 5 ヶ月ある**。主要 MLX wheel が存在しない段階で移行を始めるメリットがない。
- **2026-05-05 以降（Beta 1 / feature freeze 後）**: 依然 HOLD。ただし `pyenv install 3.15.0b1` を **別スコープ**（`~/tmp/py315-test/`）で触って PEP 810 lazy import と `profiling` パッケージの体感確認は有益。**本番 AIOS への反映はしない**。
- **2026-10-01 以降（3.15.0 Final）**: STAGED に昇格。フェーズ 1（観察）開始。
- **mlx >= X.Y.Z（cp315 wheel 同梱）がリリースされた翌週**: GO 条件成立。フェーズ 2（side-by-side install）へ。
- **3.15.1 以降（2026-12 頃）**: 本番切替可。

### 本日（2026-04-23）取るべきアクション

- コード変更: **なし**
- インストール: **なし**
- 監視: 以下の 3 本を週次でポーリング
  1. `curl -s https://pypi.org/pypi/mlx/json | jq '.info.version, .info.classifiers'` — cp315 wheel 登場の検知
  2. [blog.python.org/](https://blog.python.org/) — Beta / RC / Final リリース告知
  3. [github.com/ml-explore/mlx/releases](https://github.com/ml-explore/mlx/releases) — MLX 側対応
- 準備: `pyenv update` を次回の保守ウィンドウで実行（副作用なし、plugin def のみ更新、`3.15.0a8` が選択肢に入る）。

### 訂正不能の事実確認（evidence-before-claim 遵守）
- 今日時点で mlx core に cp315 wheel は **本当に存在しない**（`https://pypi.org/pypi/mlx/json` の `urls[].filename` に `cp315` 文字列ゼロ、2026-04-23 検証）。この 1 点が HOLD 判定の最大根拠。
- Homebrew `python@3.15` formula も **本日時点で不在**（`brew info python@3.15` が "No available formula"、2026-04-23 検証）。
- 3.15.0 Final 予定日 2026-10-01 は PEP 790 本体に明記、ただし過去 PEP の慣習として **遅延は起こりうる**（3.14 は予定通り 2025-10 リリース、[History of Python](https://en.wikipedia.org/wiki/History_of_Python)）。
